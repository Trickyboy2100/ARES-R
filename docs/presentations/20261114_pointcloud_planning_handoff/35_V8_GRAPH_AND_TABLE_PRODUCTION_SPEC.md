# V8 量化比较与专业图表制作规范（逐图可执行）

本文件定义**Codex需要真实制作的图**，不是提醒“加强可视化”四个字。全部图应使用源PPT/仓库原始CSV/JSON/归档点云重新导出，单独保存PNG/SVG（或PPT原生图表），并保存绘图代码和CSV；**不得仅粘贴旧整页截图、不得根据图形臆造数据点**。

## 1. 全篇统一的可读性“语法”

### 视觉任务定位
每页原生绘制一个不超过0.3in高的阶段定位条：
`O 实测观测 → S 场景几何 → P GPU规划 → E JAKA执行 → V 核验/恢复 → B 功能块/ROS`。
只强调本页涉及的段，并在图表角落写“指标层面：几何保真/耗时/可行性/控制误差/任务完成/交付状态”。
**阶段位置须视觉突出，不得仅在文字脚注提及。**

### 图表的六项硬性元素
1. 两端对象/版本/数据组：`P3.4 5mm vs 7.5mm`，而不是模糊的“前/后”；
2. y轴量纲、朝向：`时间 s ↓越短越好`，`最小净空 mm ↑越大越好（同时看30mm门槛）`；
3. 两端绝对值：如4.039→3.191s，避免只有相对%；
4. 差额：`−0.848s（−21.0%）`；负号和好坏状态用真实约束解释；
5. 同一工况/不同工况标志：不具可比性时禁算改善%；
6. **物理任务意义**：例如“处于场景构建阶段：保留箱体，同时降低下一次规划等待”，而不是空泛“算法更优”。

### 色彩与布局
- 旧基线灰蓝；候选/经选用深青；失败拒绝采用BBMG红＋“拒绝”文字；待验收灰色空心；阈值红色虚线；
- 颜色不能代替文字，图中直接写“可用/结构丢失/门槛未达/仅软件回归/ROS尚未实机”；
- 并列图用**同坐标、同ROI、同镜头、同采样表达和同点大小**，每张显示面积至少等于整页1/6；要看得见关键局部；
- 主体真实图片≥约55%或图表≥约55%，放不下删正文移到备注；
- 数字标注不小于一般正文可读字号（建议数字17pt以上，注释14pt以上），不得把20列数据塞进小图；
- 主图导出建议至少1600×900px（复杂点云≥2000px宽），每张另附`data.csv`、`plot.py`或可编辑PPT chart source；
- 原模板字体黑体/Arial，Logo/红线不替换；可用原生PPT图表+单独真实图做子元素，不把整页做成位图。
