# 正文03｜体素分辨率经过5、7.5、10mm实测比较，兼顾处理速度与结构完整性

**页面主结论：** 在P3.4测试工况下，7.5mm是兼顾场景处理时间和箱体结构保留的选用配置；10mm虽快但已出现结构碎裂/丢失。

**建议直接上屏文稿：**

> 为确定点云空间采样分辨率，在同一P3.4测试工况下比较5mm、7.5mm和10mm三种体素设置。  
>   
> 5mm：处理4.039s，生成243个基元；  
> 7.5mm：处理3.191s，生成171个基元，保留已知箱体观测；  
> 10mm：处理2.672s，但箱体观测出现碎裂/丢失。  
>   
> 本次测试采用7.5mm作为该工况下的折中配置。

# 正文05｜支撑层检测与凸起分解：避免把相连点云直接当作实心障碍

**页面主结论：** 针对箱体与泊位/支撑结构点云连通造成的整体包络误占据，开发基于高度层、法向和连通性的支撑—凸起分解。

**建议直接上屏文稿：**

> 现场箱体与泊位支撑结构在点云中连成一体，直接使用单个AABB会把真实间隙填充为障碍。  
>   
> 研发采用高度分箱、水平支撑带、法向水平性和局部连通性分析，分离支撑面与凸起对象；未分类实测点继续作为保守占据保留。

**关键参数小表：**

| 处理参数 | 当前实现配置 |
|---|---:|
| 支撑高度分箱 | 5mm |
| 支撑带宽 | ±10mm |
| 支撑候选最少点数 | 120 |
| 支撑最小跨度 | 100mm |
| 凸起最小高度 | 25mm |
| 局部连通邻域 | 18mm |

只展示最重要的4–5项，其他放讲者备注。

**真实几何结果：**

- 原连通大包络约209×586×274mm；
- 分离后的独立箱体候选约209×89×206mm。

这两个尺寸描述不同语义对象，不能计算或宣传为“包络缩小百分比”。

**画面内容：**

- 左侧：同一带箱诊断场景，灰色原始点云。
- 中部：支撑层候选与凸起对象颜色区分。
- 右侧：独立箱体和保留支撑/未知结构的局部几何图。
- 底部：标注“支撑/结构/未知观测继续保留，未观测空间不自动视为自由空间”。

**讲者备注：**

实现位于support_decomposition.py。支撑候选由5mm高度直方图、±10mm层带、法向水平性、XY跨度和连通性综合判断；相对支撑高度超过25mm的点进入凸起候选。该实现是确定性几何处理，不是语义神经网络。当前参数来自实际工程配置和诊断，不等于已经做过完整的参数最优性扫描。若2×2独立消融没有完成，不要声称支撑层和网格细分各自贡献了多少。

> - 点到最近P2 OBB距离至少30.01mm；

**页面主结论：** 规划输入不是单个XYZ，而是绑定当前机器人状态、双臂/工具几何、目标位姿和版本化场景的完整请求。

>   
> 规划请求统一绑定：当前关节状态、活动臂/另一臂、夹爪与工具模型、BODY目标位姿、SceneSnapshot及其版本、规划约束和轨迹哈希。  
>   
> 规划成功不直接驱动机械臂，轨迹还需完成关节映射、独立环境核验和原生执行包检查。

**实例一：TCP语义核对**

- 现场装配粗测约145mm；
- 工具网格远端约149mm；
- 控制器TCP z=184.380mm。

三者含义不同，不可直接相加，也不能把控制器TCP超出网格的长度直接补成实体碰撞柱。9/22报告中该物理语义仍未关闭，因此该版本仅规划预览。

**实例二：关节输出映射修复**

- 求解器输出201个采样×7个关节；
- 按joint_names提取joint1–joint6；
- 输出201×6；
