## 顺序

### A. 先核对原文件，不重犯替代模板错误

对06清单中的三个PPTX逐一找到实际文件并计算SHA256。可在用户授权的现有工作目录、附件目录查找精确文件名及其(1)版本；不要漫无目的扫描无关个人文件。

当前GitHub交接包**不包含这些原PPT二进制**。只有文本恢复和原有repo素材。若确实缺失，交接状态必须标缺失；不得用类似主题重绘并声称用了指定模板。大文件可以用本目录归档工具拆为40MiB字节片、核验后入库，或在具备已有LFS方案的环境按仓库约定处理。

旧16页PPTX/PDF是被否定的视觉半成品，仅作内容备份。找回它不代表找回指定模板。

### B. 素材提取与来源表

展开三个PPT全部页面；按真实页序提取图片和讲者备注；对大PPT末尾页做带原页码的联系表。

每个新页面建立来源映射：源文件/页码/媒体对象/源数据集/代码或日志/指标定义/状态。无原图时可到同源repo图集取高清版本，但必须匹配数据集。

### C. 保留16页叙事，修掉已发现的证据问题

使用02中的实际页序，不新增算法原理章节。03账本中新增的来源审查是必须修订项：32→235不是GRASP V3；GRASP V3严格几何A/B与真实GPU重放为不同世界；独立world不等于独立self-collision；两例ServoJ曲线均abort。

旧稿第1页“四轮”及第8/9页某些“从旧方法到新方法”的标题只是组织语言，不证明真实历史按这条路线发生。无提交/日志证据时改为真实功能研发叙述，仍保留页位与主题。

### D. 具体版式

先实际渲染原模板，测量布局后再排版。正文每页一个主判断，图占主区域，旁边用简短文字标问题/诊断/修改/复测。图注和关键限定留在页面上，长参数、原始路径与讲述放备注。不能用一页缩略图墙代替清楚的证据。

真实旧新图保持同视角/比例。表格与数字使用Arial，不使用装饰性大标题挤占证据区。不要修改截图内的实验数字。不要上传字体文件。

### E. 备注和状态

每页备注至少包含：怎么讲、具体改了什么、对应来源、哪些结论不能推出。第15/16页用明显标签写“尚未执行/待补证”，全部结果格留空或待测。

录音中讨论的5次重试、20秒/100多秒、3cm/5cm只能作为“需要日志验证的例子”，不得入结果图。重试数或参数寻优缺证时保留缺口，不编造。

### F. 验收与交付

产出：

- `output/点云场景重建与机械臂规划_研发过程与工作量汇报_原模板精排版.pptx`
- `output/preview/`每页PNG，另附整体联系表；环境支持时导出PDF。
- `output/speaker_notes.md`
- `output/slide_sources.csv`或JSON：16页来源、数据集、日期、状态、限制。
- `output/qa_report.md`：字体、比例、16页计数、备注、链接、图片质量、溢出、对齐、补证隔离、实际渲染结果。
- 更新06原文件转存状态与SHA256；给出最终commit和准确入口。

PPTX必须实际可打开；逐页看过渲染后才写“版式检查完成”。某种字体缺失、视频不兼容、原图找不到或PDF未导出都应列明。不把脚本/任务书当成完成的精排PPT。
