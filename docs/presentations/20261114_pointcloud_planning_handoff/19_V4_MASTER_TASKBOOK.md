**3.2 自适应几何感知的机械臂控制策略研发——点云场景重建与机械臂运动规划控制**

## 2. 汇报范围与核心主线

### 工作包A：真实点云驱动的场景重建与碰撞几何编译

- CAMERA/BODY坐标和采集状态一致性；
- 工作区ROI、体素分辨率、数据压缩；
- 机器人自体点归属和过滤；
- 离群点净化、DBSCAN聚类与参数选择；
- 支撑层检测、凸起与连通结构分解；
- 粗AABB误占据归因、局部多基元精化；
- SceneSnapshot和cuRobo碰撞世界编译。

### 工作包B：cuRobo规划适配、性能优化与JAKA实机控制

- JAKA Mini2 URDF、工具/TCP、左右臂及关节映射；
- BODY目标、当前关节状态、环境障碍和规划约束绑定；
- cuRobo碰撞代价、规划参数与负结果筛选；
- seed、CUDA Graph、常驻planner和动态world更新；
- 轨迹映射、重采样、重定时、独立环境核验；
- JAKA ServoJ执行、跟踪反馈、近障起点退出；
- 任意运行时目标、真实障碍物规划；
- 持物对象几何归属、故障诊断和检查点恢复。

两部分的主线是：

**真实点云 → BODY空间与自体归属 → 结构分解 → 碰撞几何编译 → cuRobo规划请求 → 轨迹独立核验 → JAKA ServoJ执行 → 现场反馈/重新观测/恢复。**

RASC是本项目场景几何编译能力的统一称谓，不代表项目发明了DBSCAN、AABB、OBB或cuRobo。cuRobo是成熟求解器；本项目的研发贡献是其面向现场工位、机器人、工具、环境和执行控制的工程适配、约束、验证和集成。

## 5. 研发事实与验证等级

每页正文或页脚必须用简短方式标记数据性质：

- **冻结离线回放**：原始数据固定、无硬件运动；
- **规划级验证**：求解和模型核验完成，但没有物理执行；
- **受监督实机执行**：有控制器实际读回、到位和fault/abort记录；
- **实机故障恢复**：保留原故障，后续从检查点接续；
- **软件回放/故障注入**：证明软件流程，不等于现场物理任务完成；
- **待补证/未执行**：只可出现在附录或内部缺件报告，不能写成已完成成果。

必须保留以下边界：

- S21-CLEAN、S21-ATTR、S21-CLEAR7、S10-CAMERA、S21-GRASP-V3不是同一输入，不能拼成一组前后实验。
- P3.3的12次规划均未达到30mm模型净空门槛，全部拒绝放行；不是实机成功，也不是60次完整扫值。
- P3.3的collision activation distance是代价激活阈值，不是所得轨迹的最小净空保证。
- P3.4的5.095s/6.822s是正式求解时间P50；14.780s/17.759s是包含其他环节的warm request wall P50；不能互换。
- P3.4的0.20rad/s仅属于RIGHT_ARM_AB_DEMO_ONLY commissioning profile，不是全站通用速度。
- P3.6/P3.7的gap均是模型几何间隙，不是物理测距保证；独立world核验不等于独立自碰认证。
- P3.7五段是自由空间/绕箱运动，不是完整抓取、接触或放置。
- S19-PLACE是故障恢复后完成，不是同一脚本无人干预的一键连续成功；持物模型修正是Demo限定，不代表通用自动持物估计已经完成。
- P3.8E的400.25s为native-ready→HOLD窗口；1266.92s观察→HOLD含交互调试与人工交接；完整全任务周期没有被该审计实测。
- 10/21三个CPU模块加速倍数互不相加，不能宣传为整任务11倍加速。
- P3.9中的395s是工程模型/估计，不是实测完整任务周期；除非专门作为“估计”附录，不进入已实现结果。
