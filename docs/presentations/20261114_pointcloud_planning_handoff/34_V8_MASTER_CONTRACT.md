## 3. 全篇必须建立“任务阶段—性能层面”双坐标

每一页上部或底部放一个精简的原生PPT任务阶段带（**重复使用现有BBMG红线组件，不替换母版**）：

`对象识别/观测 O → 场景编译 S → 规划 P → 控制 E → 核验/恢复 V → 功能块交付 B`

每页只高亮相关1–2阶段，另用小字给出性能维度：
`几何保真 / 时延 / 约束可行性 / 执行精度 / 故障鲁棒性 / 现场复用`。

每个结果图的角落必须答出：
- **在哪一阶段**（例如：点云编译，不是机器人速度）；
- **改善什么量**（例如：构建耗时↓20.99%；保留箱体可用=通过）；
- **什么越大/越小越好**（显示箭头和单位，不能只用柱高）；
- **对后续动作的影响**（例如避免空隙被误占据、减少求解等待、保障持物后继续规划）；
- **比较是否同源**（同帧/同场景/不同任务/离线/实机）。

## 4. 每页至少一张“能判断”的图，不能是另一张抽象流程图

优先图型：
1. **同帧同坐标 OLD|NEW放大图**：展示几何差异；不允许两张看不见主体的3D截图；
2. **目标/约束门槛图**：红色阈值线，真实轨迹或数据点明确位于可行/不可行侧；
3. **前后绝对值＋相对变化**：条形图＋数值标签＋百分比，0轴、单位和方向统一；
4. **代价—保真二维Pareto对照**：用于体素、聚类、几何多基元权衡，不冒充单指标最好；
5. **任务阶段时序与漏斗**：用实测阶段起止时间图标识提升发生在OBSERVE/PLAN/EXECUTE哪一级；
6. **功能块验收矩阵**：Native原生、ROS源码/部署、ROS实机、Delivered分别标示；功能目录数量不等于通过数量；
7. **真视频分镜**：3–5真实关键帧＋实际任务阶段条＋对应原始运行ID，不用整张低清截图填满。

每页采用：主图55–70%面积；原生高对比数值表20–30%；最下一行不超过25字的“工程结论＋工况限定”。若图不支持结论，结论必须降级。

### 配色与判断语义
- 基线/历史：钢蓝或灰蓝；
- 本轮优化/可用：深青；
- 拒绝/失败：BBMG红；
- 未验收/待证据：灰＋斜线/空心圆；
- 目标门槛：深红虚线。

- 不允许使用彩色badge冒充研究结果，输出是PPT中的统一原生图表。

## 6. 实测性能归因与比较边界

例子：
- 5→7.5mm体素：4.039→3.191s，减少0.848s/约21%，且同工况关键箱体观测保留；10mm虽更快却碎裂，**没有简单“越快越好”**；
- 4/4→4/2种子：12.00→5.06s，求解P50缩短约57.8%（限定P3.4工况）；4/2 Graph开关仅5.06→5.04s，差0.02s不夸大；
- S10几何体积和−40.9%，观察点覆盖100%，基元32→235；**基元数增加不能写成改进百分比，体积和≠实际自由空间增加**；
- P3.3四档12/12未达30mm门槛：不能用这个负结果写提升；
- P3.4 CLEAR整次warm request14.780s，其中formal solve5.095s（34.5%）；AVOID 17.759s/6.822s（38.4%），剩余时间还包含其他模块，不能擅自分给某个阶段；
- CPU 17.023→1.125s等仅模块级benchmark；不得作为整体任务加速；
- 11/20筛网156.63s与11/18天平放置168.10s是**不同任务**，只能“各任务完成用时”，不可做“提升7%”对照；
- 11/17 Demo02前半段63.02→45.56s是不同起点/路径，不得以约27.7%宣称并行带来的因果提速；
- 同场景冻结回放首完整请求10.302s、热请求3.805–3.901s和solve约1.55s，可同页画**运行状态对照**，但不代表含扫描及实际运动的整个任务提速。
