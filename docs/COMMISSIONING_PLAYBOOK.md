# 视觉抓取联合调试手册

## 目标与边界

目标流程固定为：检测 → 规划 → 预抓取 → 短距接近 → 夹紧 → 抬升 → 再检测 → 规划 → 预放置 → 短距放置 → 松开 → 撤离。

规划与执行必须分层。Epic Pro 或 cuRobo 只产生候选位姿或轨迹；ARES-R 负责协议解析、坐标变换、轨迹验证、状态机和留痕；JAKA SDK 只执行已通过门禁的轨迹。复杂空间不得用单条 `linear_move` 代替避障规划。

## 已核实结论

| 问题 | 结论 | 工程要求 |
| --- | --- | --- |
| Epic 避障是否来自点云 | 部分来自。场景点云与匹配结果模型均可作为动态障碍；点云先被八叉划分到设定网格尺寸，再进行碰撞判断。静态场景模型同样属于障碍来源。 | 固定台面、箱体、底盘、另一机械臂优先使用稳定模型；临时物体使用点云或匹配模型。网格越小越精确，计算时间越长。 |
| 仅末端避障还是整臂避障 | 由碰撞矩阵决定。官方矩阵支持机器人关节、工具、场景对象、动态障碍之间的碰撞对。 | 必须启用各机器人关节与场景、工具与场景、自碰撞、双臂互碰等碰撞对；仅配置 TCP 或末端模型不构成整臂避障。 |
| TCP 前伸与夹持料盘 | TCP 只定义运动参考原点，不代表实体体积。工具 OBJ 用于碰撞检测；料盘夹持后形成新的附着碰撞体。 | 建立空夹爪工具模型与“夹爪+料盘”附着模型；抓取前后切换模型版本；模型覆盖最大外廓并增加安全余量。 |
| Epic 路径如何交给 JAKA | 5700 返回笛卡尔或关节路径点，不直接调用 JAKA。 | Epic 选“关节”返回类型，保存原始报文和关节序；完成时间参数化与门禁后，密集轨迹使用 `servo_j`；稀疏目标点可评估 `joint_move_extend`，不得把稀疏点直接高速送入 `servo_j`。 |
| `servo_j` 还是 `linear_move` | JAKA 官方说明：`joint_move` 的插补由控制器完成，`servo_j` 需要预先规划轨迹，发送周期为 8 ms，扩展周期为 `step_num × 8 ms`。 | 全局避障段使用规划后的关节轨迹；抓取和放置附近的短直线段只有在完整碰撞验证后才允许使用低速 `linear_move`。伺服模式内禁止调用 `joint_move` 或 `linear_move`。 |
| 奇异点 | 笛卡尔直线运动可能经过奇异区域；关节运动不受笛卡尔奇异描述直接约束。 | 规划时限制雅可比条件数或最小奇异值，加入关节限位余量，求解多个 IK 分支；全局段采用关节路径绕行，短直线段预先逐点求 IK。 |
| 正抓与反抓 | 两指夹爪可生成绕接近轴相差 180° 的抓取候选。 | 两个候选分别完成 IK、整臂碰撞、工具碰撞、可操作度、关节余量和路径长度评分；禁止仅按末端距离选取。 |
| 平滑性 | 几何无碰撞不等于可执行。 | 轨迹必须重采样、限速、限加速度、限跃度；起点速度与终点速度按任务阶段设定；JAKA 滤波仅作补充，不得掩盖不连续轨迹。 |

## 统一接口

统一轨迹文件见 `examples/trajectory.example.json`，内部单位固定为弧度和秒。关键字段：

- `joint_names`：顺序必须与 JAKA 状态回读一致。
- `sample_period_s`：必须为 8 ms 的整数倍；现场首轮建议 80 ms，再逐级降低。
- `collision_checked`：几何规划器必须明确写入。
- `robot_model_revision`、`world_revision`、`tool_revision`、`attached_object_revision`：防止模型与实物错配。
- `points`：稠密关节轨迹，不接受笛卡尔点直接进入执行器。

离线检查命令：

```text
motion inspect examples/trajectory.example.json
motion validate examples/trajectory.example.json
```

示例限位配置故意保留 `commissioning_confirmed=false`。现场核对型号、控制器软限位、负载、工具和速度后，复制为现场配置并改为 `true`；未确认状态始终阻断执行。

`src/ares_r/adapters/jaka_servo.py` 提供独立的 JAKA 执行骨架，包含实时状态预检、显式 `armed=True`、绝对关节点发送、周期检查、队列检查、异常 `motion_abort` 和伺服模式退出。该执行器未注册到 Terminal 工厂，因此当前 Terminal 仍无法驱动机械臂。

## 路线一：Epic Pro 规划

### Epic 配置

1. 导入准确的 JAKA MiniCobo 机器人包；核对基座坐标、关节零位、关节正方向和关节顺序。
2. 导入夹爪凸包或凸组合 OBJ；设定真实安装位姿和 TCP。
3. 新增“夹爪+料盘”模型；覆盖料盘、夹爪、法兰、相机支架和线缆高风险区。
4. 建立静态场景模型；更新点云裁剪范围，排除机器人自身点云和无关背景。
5. 配置碰撞矩阵：全部臂段对环境、工具对环境、臂段自碰撞、双臂互碰、附着料盘对环境。
6. 抓取路径设置起始点、预抓取点和抓取点；撤离路径设置预撤离点和终点。
7. 返回位姿类型选择“关节”；关节角差阈值设置为小于 ARES-R 单段门限。
8. 规划器首选关节空间或贝塞尔；线性规划器只用于已知无障碍短段。

### 5700 协议

- `220,n,0`：拍照并规划抓取路径。
- `220,n,m`：拍照并规划抓取路径与撤离路径。
- 返回头包含 `poseType` 和 `sentPoseCount`；`poseType=1` 表示关节点。
- 当前终端可离线解析保存报文：

```text
epic parse "220,1,2,..."
```

Epic 规划点没有 JAKA 伺服时钟语义。报文不得直接逐点发送；先转换成统一轨迹，执行重采样和时间参数化。

### JAKA 执行阶段

1. 回读机器人状态、关节位置、限位状态、碰撞状态、急停状态和使能状态。
2. 比较当前关节与轨迹首点；任一关节误差超过现场阈值时阻断。
3. 关闭残留伺服模式；必要时用低速 `joint_move` 到已验证的轨迹首点。
4. 启用 `servo_move_enable(True)`；按 `step_num × 8 ms` 的稳定时钟发送绝对关节点。
5. 每周期监控 SDK 返回码、队列长度、软限位、碰撞和跟随误差；异常立即停止发送并调用 `motion_abort`。
6. 正常结束后退出伺服模式；回读终点状态并写入日志。

首轮真机验证只允许：单臂、空载、无遮挡、低速、短轨迹、急停可达、另一机械臂停在已验证安全位。负载抬升必须在空载路径重复验证后开始。

## 奇异与限位恢复

### 预防

- 目标 IK 至少生成正抓、反抓和多个关节种子。
- 评分项包含：最小碰撞距离、关节软限位余量、雅可比最小奇异值、关节总位移、腕部翻转量。
- 接近段和撤离段逐点求 IK；禁止只检查端点。
- 轨迹首尾增加减速段；腕部姿态变化过大时拆分为安全位重定向与抓取接近两段。

### 真实限位

1. 立即 `motion_abort`，停止伺服点发送，退出伺服模式。
2. 保存 `get_robot_status`、`is_on_limit`、当前关节、目标关节和最近轨迹窗口。
3. 禁止重复发送原目标，禁止自动调用 `collision_recover` 处理限位；该接口只对应碰撞保护恢复。
4. 根据示教器状态确认可退出方向；低速 JOG 或已验证 MoveJ 退出软限位区。
5. 无法确认方向、硬限位、持续报警或制动异常时保持停止，由设备维护流程处理。
6. 修正坐标变换、IK 分支、软限位余量或模型后，从空载低速门禁重新开始。

### 碰撞保护

先移除外力或接触原因，再核对 `is_in_collision`。满足设备手册恢复条件后调用 `collision_recover`；恢复只解除保护状态，不代表原路径安全，原路径必须废弃并重新规划。

## 平滑轨迹验收

- 位置连续：任意相邻点无关节跳变。
- 速度连续：首尾接近零，段间不出现符号瞬变。
- 加速度与跃度受限：现场参数低于机器人额定能力并保留负载余量。
- 周期稳定：发送抖动、丢包和队列长度写入日志。
- 跟随误差受限：回读关节与命令关节同步记录。
- 碰撞复核：重采样后的最终轨迹重新进行整臂、工具和附着物碰撞检查。

## 阶段门禁

| 阶段 | 输入 | 通过条件 | 输出 |
| --- | --- | --- | --- |
| V0 感知重复性 | 固定场景多帧点云 | 位姿均值、标准差、离群率可复现 | 标定后的抓取候选 |
| P0 离线规划 | 模型、点云、候选位姿 | 整臂无碰撞、软限位有余量、无奇异 | 统一轨迹文件 |
| E0 静态检查 | 轨迹、现场限位 | `motion validate` 无错误 | 签名轨迹 |
| E1 空载低速 | 单臂短轨迹 | 无报警、无跳变、跟随误差合格 | 现场执行参数 |
| E2 空载全程 | 全任务轨迹 | 重复执行稳定 | 空载基线 |
| E3 负载抬升 | 附着料盘模型 | 低高度抬升稳定、负载参数正确 | 负载基线 |
| E4 联合流程 | 感知、规划、执行 | 状态机与异常恢复完整 | 可回归任务 |

## 留痕要求

每次运行保存：Git 提交号、配置哈希、机器人/工具/场景模型哈希、原始点云标识、Epic 原始报文、规划器版本、轨迹文件、JAKA 状态窗口、结果与失败代码。禁止覆盖原始记录；调参产生新运行编号。
