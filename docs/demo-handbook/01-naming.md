# 编号、工位与对象

## 五位核心编号

`入口(1位) + 工位范围(2位) + 功能(1位) + 泊位(1位)`

| 字段 | 值 | 含义 |
|---|---|---|
| 入口 | A / R | ART/WebUI 原生 / ROS 交付目标入口 |
| 工位 | AW、A0、B1、B2、B3、C0、D1、D2 | 见下表 |
| 功能 | F / P / U | Fetch 取 / Place 放 / Utility 通用辅助 |
| 泊位 | 0 / 1–6 | 默认占位 / 烘干箱六泊位 |

`RB2F2` 表示 ROS、烘干机中间范围、抓取上中泊位。`AB2P5` 表示原生、烘干机中间范围、放入下中泊位。同一业务对使用 A/R 两个编号，共用功能实现和参数合同。

## 工位范围

| 编号 | 名称 | 绑定状态 |
|---|---|---|
| AW | 无特定工位要求 | 仍需当前场景、工具与可达性满足所选任务 |
| A0 | 料盘天平前 | 目录命名确定；旧 GRASP 记录通过站位表映射保留 |
| B1 | 烘干机左列范围 | 对应1/4泊位；实际 SLAM pose 待逐站绑定 |
| B2 | 烘干机中列范围 | 对应2/5泊位；下中成功证据可复用，数值站位待绑定 |
| B3 | 烘干机右列范围 | 对应3/6泊位；实际 SLAM pose 待逐站绑定 |
| C0 | 筛网天平前 | 对接旧 SIFT-BLC-GRSP，具体坐标版本单独绑定 |
| D1 | 除尘收料专机筛网范围 | 本版建议分配，待站位绑定确认 |
| D2 | 除尘收料专机料盘范围 | 本版建议分配，待站位绑定确认 |

D1/D2 按对象区分是本版命名提案，两者可以绑定同一实际底盘位置，也可以分开。B1/B2/B3 是业务范围；上下层能否共享一个实际站位以可见性、可达性和完整持物空间验证为准。

## 泊位顺序

面向烘干机开口，从左到右。

| 层 | 左 | 中 | 右 |
|---|---|---|---|
| 上层 | 1 / upper_left | 2 / upper_middle | 3 / upper_right |
| 下层 | 4 / lower_left | 5 / lower_middle | 6 / lower_right |

上中抓取为 `AB2F2 / RB2F2`，下中放置为 `AB2P5 / RB2P5`。泊位号与 Epic 配置 ID 分开保存，ID3 识别参考点后可以派生六个偏置目标。

## 变体后缀

同一核心功能的不同末状态或实验版本增加 `-01`、`-02` 等两位后缀。基础业务表保留五位码；别名映射显式登记变体，禁止通过省略后缀猜测 Utility。

- `AAWF0` 不使用，AW 无具体抓取工位。
- `AAWU0-01 / RAWU0-01` 为右臂回 center。
- `AAWU0-02 / RAWU0-02` 为右臂 center → 已保存姿态往返，即已交付 Demo01。
- `AA0F0-02 / RA0F0-02` 为料盘原位抓放 reset 测试分支。
- `AC0F0-02 / RC0F0-02` 为筛网原位抓放 reset 测试分支。
- `AA0F0-03 / RA0F0-03` 保留历史料盘 first-pick 抬升100mm并持稳版本。

默认操作臂记录在参数 `arm=right`，版本、速度、Golden/Delivered 状态和算法模式均作为 metadata。未来左臂复用核心业务号时，新增明确变体及 arm 字段。

完整跨工位任务采用独立 Scheme 编号，例如 `S-A0-B2-01`，关联多个 F/P 功能及导航。避免用单个取或放编号隐藏底盘转场。

## 兼容迁移

旧 demo_id、Console alias、ROS Action 和历史证据路径保留。新目录记录 `native_code / ros_code / legacy_alias / executor / profile_revision / evidence`。第一步仅展示新名称和映射，后续独立增加别名解析并验证一一对应，再开放新编号启动。已有客户端继续使用原 Action。
